## Current project shape

- Existing Next.js App Router app.
- Next.js `16.3.4`, React `19.2.8`, Tailwind CSS 4.
- No Clerk SDK is currently installed.
- No existing auth provider was found.
- No `proxy.ts` or `middleware.ts` currently exists.
- The home page has a header with placeholder notification and profile controls.

## Setup checklist

1. Check whether the Clerk CLI is available.
2. Install or update the Clerk CLI if needed.
3. Run `clerk auth login` from the project root and pause if the user must finish browser login.
4. Run `clerk init --app app_3J3KhbXFVjnE5r5s9y2hVxbH6rC` from the project root.
5. Verify the generated Next.js integration.
6. Ensure the Next.js 16 proxy matcher includes Clerk's auto-proxy path:
   - `'/(api|trpc)(.*)'`
   - `'/__clerk/:path*'`
7. Add visible sign-in, sign-up, and signed-in user controls to the home header.
8. Run `clerk doctor`.
9. Start the app and manually verify the controls.

## Decisions and assumptions

- This is an existing project, so `clerk init` should detect the framework and package manager.
- Use `@clerk/nextjs`, not `@clerk/react`.
- Place `ClerkProvider` inside `<body>` in `app/layout.tsx`.
- Keep the landing page public.
- Add Clerk auth controls directly into the existing header so the UI remains close to the provided home design.
- Replace the placeholder profile avatar with Clerk's signed-in `UserButton`.
- Show `SignInButton` and `SignUpButton` only when signed out.
- Keep the notification button presentational for now.
- Do not add route protection beyond Clerk's project proxy setup unless the CLI scaffolding requires it.

## Security considerations

- Never expose `CLERK_SECRET_KEY` in client code.
- Do not print or copy existing `.env*` contents into chat.
- Only `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` may reach the browser.
- Auth state in the UI must come from Clerk components, not hand-rolled client state.
- Future protected routes or server actions must call `await auth()` on the server.

## Requirements

- Clerk CLI must be used for setup.
- The project must link to `app_3J3KhbXFVjnE5r5s9y2hVxbH6rC`.
- The app must compile with Clerk installed.
- Header must have clear signed-out and signed-in controls.
- Next.js 16 must use `proxy.ts`, not a new `middleware.ts`.
- The proxy matcher must include Clerk's `'/__clerk/:path*'` path.

## Acceptance criteria

- Signed-out users see Sign in and Sign up controls in the header.
- Signed-in users see Clerk's user/account button in the header.
- The home page remains public.
- Clerk provider is mounted in the root layout.
- `clerk doctor` reports no blocking integration issues, or any remaining issues are documented.
- Lint, type check, build, and dev server checks complete and are reported honestly.
